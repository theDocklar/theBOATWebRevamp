## Frequently Asked Questions

**Is self-hosted n8n difficult to maintain?**  
If you have DevOps capacity: no. It's a Docker container with a PostgreSQL database—standard web app stack. If you don't have DevOps: we offer managed hosting (we maintain the infrastructure, you focus on workflows). Most enterprises self-host for data control; most SMBs choose our managed option.

**Can n8n integrate with [our specific tool]?**  
n8n has 400+ pre-built nodes (Salesforce, HubSpot, Stripe, Shopify, QuickBooks, Slack, Gmail, AWS, Azure, Google Cloud, etc.). If your tool has an API, we can integrate it. If it doesn't have an API, we can scrape it or use RPA (browser automation).

**What happens if a workflow breaks?**  
n8n includes built-in error handling: retry logic (up to X attempts with exponential backoff), fallback workflows (if this fails, do that), and alerting (Slack/email when error threshold exceeded). We also set up monitoring dashboards showing success rates, execution times, and error patterns.

**Do we need to know how to code to use n8n?**  
No. n8n is primarily drag-and-drop nodes. But when you need custom logic (data transformation, business rules, calculations), JavaScript/Python code nodes unlock infinite flexibility. We build the workflows—you maintain them via UI.

**How is data secured in self-hosted n8n?**  
- API credentials: Encrypted at rest in PostgreSQL
- Data in transit: SSL/TLS for all external connections
- Access control: SSO integration (Google, Okta, Azure AD), role-based permissions
- Audit trail: Every workflow execution logged with inputs/outputs
- Network: Runs in private subnet, only exposes webhook endpoints via reverse proxy

**Can we migrate from Zapier/Make to n8n?**  
Yes. We've migrated dozens of clients. Process: (1) Export Zapier/Make workflows (or recreate from documentation), (2) Rebuild in n8n with improved error handling and efficiency, (3) Test in parallel with old system, (4) Cut over when validated. Typical migration: 2-4 weeks depending on workflow count.
